# GCP/Terraform infrastructure

This feature adds the first manual deployment configuration for the Go and
Node APIs on Google Cloud Run. Terraform manages the required product APIs,
one regional Docker Artifact Registry repository, both Cloud Run services, and
their non-secret outputs. Docker image builds and pushes remain outside
Terraform.

## Deployment topology

Both services are temporarily public in `southamerica-west1`:

```text
Client → interseguro-go-api (Cloud Run) → interseguro-node-api (Cloud Run)
       QR/factorization                         statistics
```

The Go service receives `NODE_API_URL` from the computed Node Cloud Run URI.
Neither service has a hardcoded `PORT`; each application continues to read the
Cloud Run-provided value. Runtime instances are configured with 0–3 instances,
1 vCPU, and 512 MiB memory.

The temporary public-to-public arrangement is intentional for this phase.
Service-to-service IAM, authentication tokens, private ingress, VPC access,
secrets, and other hardening are not included.

## Terraform configuration

The configuration lives in `infrastructure/` and requires Terraform `>= 1.16.1,
< 2.0.0` with the `hashicorp/google` provider `~> 8.1`. The provider uses
Application Default Credentials and accepts the following variables:

| Variable | Purpose |
| --- | --- |
| `project_id` | Google Cloud project that owns the resources |
| `region` | Shared Artifact Registry and Cloud Run region |
| `artifact_registry_repository` | Regional Docker repository name |
| `go_service_name`, `node_service_name` | Cloud Run service names |
| `go_image`, `node_image` | Complete image references with explicit non-`latest` tags |

Copy `infrastructure/terraform.tfvars.example` to the ignored local file
`infrastructure/terraform.tfvars` and adjust values as needed. Do not commit
the local variables file, credentials, Terraform state, or the `.terraform/`
directory. The provider lock file, once generated by a local initialization,
should be committed.

Terraform outputs are `artifact_registry_repository_url`, `node_service_url`,
and `go_service_url`; none contains a secret.

## Operational boundary

The approved deployment sequence requires a one-time targeted bootstrap for
the two product APIs and Artifact Registry repository, followed by external
Docker Buildx image pushes and a normal full Terraform apply. The repository
README contains the exact commands and the expected `linux/amd64` image tags.

Per the current review request, no Terraform, `gcloud`, Docker, initialization,
validation, planning, applying, or cloud-side command has been run. Deployment
and runtime verification remain deliberately deferred for manual review.
